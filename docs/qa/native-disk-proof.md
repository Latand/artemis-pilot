## Actual program selection

The observer arms on the existing disk material draw callback. At its next
positive native drawArrays/drawElements, after uniform upload, it inspects the
actual CURRENT_PROGRAM. Once per program it retains both linked/compiled shader
sources, the unique DISK_UNCLIPPED definition, the effective float precision and
Three's HIGH_PRECISION macro. The active mode follows those native definitions.
A CPU define or an optimized-out uniform alone is not mode evidence.

Every positive draw records native geometry uniforms, viewport and camera
conditions. Uploaded inputs must match float32 material values. The unchanged
conservative proof is evaluated against those uploaded inputs. A native fast
program needs qualified highp storage, valid geometry and an enabled disk; its
actual mode and shader define must agree with the CPU decision and current
material. This catches reuse of an old fast shader when the CPU requests a
plane-crossing fallback. Native storage capability does not certify IEEE
operation rounding or GPU arithmetic equivalence.

The observer forwards real customProgramCacheKey calls once, with original
arguments, receiver and returned key. It never calls that stateful hook merely
to inspect it and never replaces it with a constant key. It records mode/version
changes and observes production HIGH_FLOAT query results within key/compile
callbacks without issuing extra queries there. onBeforeCompile events retain
the actual precision, keyed definition and result mode. Fast compilation may
legitimately occur on a positive draw; it must satisfy the same native program,
capability and geometry evidence as a cached fast draw. Normalized compilations
must produce CPU mode0. Sticky rejection is retained across cached variants.

## Submission and lifecycle accounting

Every compile and key event links to an exact native submission or one of the
three declared non-drawing precompile calls. Draw linkage retains arm identity,
compile interval, preceding submission count, label and lifecycle snapshot.
Real zero-count submissions are forwarded and retained as skips. Their CPU
compile/key evidence is not an uploaded-uniform or selected-GPU-program claim.
An unmatched unarmed compile cannot borrow a later draw to satisfy coverage.

Three explicit cached-precompile checks run only after existing pixel captures:
the original saturn-near-lens +.48 capture and its two recovery-control captures.
Each calls the real renderer.compile on that disk after its draw arm has cleared.
The observer requires no scene-frame advance, no native draw/submission, and an
actual normalized key selection. These calls are disclosed additional untimed
work, not added warmup or timed-runner work. Their evidence is a separate entry;
they cannot replace any required capture. The next existing cases verify native
program selection again. The source-only suite separately covers the exact
cross-renderer invalidation regression and cached transitions.

All88 required production capture entries remain mandatory, with exact
phase/scenario/pitch/index and restoration epoch. All33 plane/dense-crossing
captures must select normalized native programs. All eight signed inclined
baseline/candidate whole-frame PNG pairs must be byte-identical and use a
nonvacuous actual fast program. The initial epoch and both native restoration
epochs need normalized compilation plus observed fast and normalized draws.
A cached fast-to-fallback transition is required. Raw shader records and compact
draw references must agree; omitted, duplicated or fabricated events fail closed.

The original budget remains62 saved captures,26 stability captures and629 pixel
reads per root, with132 healthy manual app-frame calls and the existing startup
frame. No app frame, render pass, native draw, screenshot or pixel read is added
for this observer. Limits remain8192 draw/skip records and64 compile/program
records, with16384 key/arm records and exactly three declared precompiles.
Truncated/error-overflow histories reject acceptance. Observation failure never
suppresses an original draw or source callback. Unrelated world draws cause no
observer GL queries. Program/texture/framebuffer bindings are never changed.

All hooks/property descriptors restore before close, including the original
stateful key function and precision-query function. Stop retains its2s deadline;
browser close retains an independent5s deadline within the existing10s outer
finalizer. Original failures, late-abort protection and independent cleanup
attempts remain unchanged. Evidence is saved before assertions.

## Local proof and remaining gate

The CPU smoke now uses the actual production callbacks and installed Three
parameter/cache code, with controlled GL reflection and uploads. It covers
native static definitions, stale-program and precision mismatches, failed
queries, zero-count forwarding through the real indexed/array buffer renderers,
precompile/frame/ledger violations, all88/33 capture requirements and independent
cleanup. It proves no browser or GPU result. Exact source/ancestor/blob pins,
all four native hook validations and the immutable cost-adapter hashes must pass
before a reviewed isolated workflow can run.

The planned workflow executes all four pixel/lifecycle modes first, then all
four original five-trial active-cost pairs only if every pixel mode succeeds.
No cost threshold, sample count, warmup, trial order or long-task limit changes.
Historical v3/v5 performance failures, v4's overly strong reset oracle failure,
and diagnostic setup failure37252663287 remain retained. The successful mode
observation37255339064 showed the old uniform path selected in its own setup;
it did not establish historical timed uniforms or clear a performance gate.
